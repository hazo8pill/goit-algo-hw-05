# goit-algo-hw-05

Порівняння алгоритмів пошуку підрядка: Боєра-Мура, Кнута-Морріса-Пратта та Рабіна-Карпа.

## Файли

- `search.py` - реалізація трьох алгоритмів
- `test_search.py` - тести (pytest)
- `benchmark.py` - заміри часу через `timeit`
- `article1.txt`, `article2.txt` - тексти статей (перекодував з cp1251 в UTF-8)

## Як запустити

```bash
pip install -r requirements.txt
pytest
python benchmark.py
```

## Як вимірював

Для кожної статті шукав два підрядки:

- існуючий - фраза з кінця статті, щоб алгоритм пройшов майже весь текст:
  - стаття 1: `Жадібні алгоритми. Distance learning`
  - стаття 2: `Zero-suppressed BDDs and their applications`
- вигаданий - `вигаданий підрядок, якого тут немає 12345`

Кожен замір - 20 викликів функції, повторюю 5 разів і беру найменший результат.
У таблиці час одного пошуку в мілісекундах.

## Висновки

**Стаття 1.** Найшвидший - Боєр-Мур: приблизно 0.15 мс для обох підрядків. КМП повільніший
десь у 6.5 раза (близько 1 мс), Рабін-Карп - у 21 раз (близько 3.3 мс).

**Стаття 2.** Теж Боєр-Мур: 0.16 мс для існуючого підрядка і 0.23 мс для вигаданого.
КМП - 1.2-1.5 мс, Рабін-Карп - близько 4.8 мс. Стаття 2 довша (18400 символів проти 12658),
тому КМП і Рабін-Карп на ній працюють довше приблизно пропорційно довжині тексту.

**В цілому.** Найшвидший алгоритм - Боєр-Мур, він виграв у всіх чотирьох замірах.
За сумарним часом він швидший за КМП приблизно в 7 разів і за Рабіна-Карпа в 23 рази.

Чому так вийшло:

- Боєр-Мур порівнює підрядок з кінця і при неспівпадінні може перестрибнути одразу на кілька
  символів. Підрядки в мене довгі (36-43 символи), тому стрибки великі і більшу частину
  тексту алгоритм взагалі не читає.
- КМП ніколи не повертається назад по тексту, але переглядає кожен символ, тому його час
  залежить тільки від довжини тексту.
- Рабін-Карп теж проходить по кожному символу, але на кожному кроці ще перераховує хеш
  (множення і ділення з остачею), а в Python це повільно. Тому він останній.

Для існуючого і вигаданого підрядка час майже однаковий, бо існуючі підрядки я брав з кінця
тексту - в обох випадках алгоритм проходить майже всю статтю. Якби підрядок був на початку,
пошук завершувався б набагато швидше.
